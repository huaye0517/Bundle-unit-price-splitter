# 组合装单价拆分工具

Windows 原生桌面工具：已内置《组合装及子件合并数据》基础库，可选择“有手续费”或“无手续费”模式，拖入销售单后生成拆分金额和订单核对汇总表。计算引擎和基础库均内嵌在单个 EXE 中。

## 基础数据与拖拽

- 首次运行会从 EXE 初始化本地基础库，后续更新会保留在当前电脑。
- “新增”按“母件编号 + 子件编号”去重追加，不覆盖已存在的组合；“覆盖”用所选工作簿整体替换当前基础库。
- 基础数据和销售单区域都支持直接拖入单个 `.xlsx` 文件，也保留文件选择按钮。
- 销售单区域默认勾选“有手续费”；无手续费销售单需先切换为“无手续费”再执行拆分。

## 计算规则

- 销售单不再依赖固定列号，按“订单编号、物流单号、网店订单号、应收合计、货品编号、数量、单价、金额、备注”等列头名自动匹配。
- 新版基础库按销售表“备注”中的“编号”匹配“母件编号”，再用“货品编号”匹配该母件下的子件编号；“组合装单价”写入对应执行价格，组内使用基础表“分摊比例”。
- 优先按“物流单号”拆分；物流单号为空时依次回退“订单编号”、“网店订单号”和单行。同一物流单号下即使包含多个网店订单号，“应收合计”也只计一次。
- 有手续费模式以“应收合计”扣除各行 `ROUND(原金额 × 1%, 2)` 的手续费合计作为拆分目标，并保留“单价2、手续费1%、最终金额”核对列。
- 无手续费模式直接以“应收合计”作为拆分目标，不读取其他工作表的“订单金额”覆盖目标，也不生成手续费相关列。
- 一个物流单组含多个母件或普通商品时，先按各组原“金额”分配净额，再在母件组内按当前出现子件的分摊比例归一化拆分。
- “备注”为空或母件与子件无法联合匹配时，相关行按 `原单价 × 数量` 比例兜底；原单价或原金额为 0 的免费子件不参与拆分。
- 若整笔正金额订单的所有原单价、原金额都为 0，则改用母件分摊比例；没有可匹配比例时按数量兜底，避免整单被误判为异常。
- “组合装单价、占比、单价、金额”插在原“单价”后。有手续费模式在原“金额”后插入“单价2、手续费1%、最终金额、摊后金额”；无手续费模式只插入“摊后金额”。
- 旧版占比表 `Sheet2` 继续按“单品编号/单价”执行原有拆分逻辑。
- “占比”：当前明细行占整个逻辑拆分组金额的比例；两位小数尾差由最后一个有效行吸收，每个有效组的占比合计严格为 1。
- 拆分“单价”：当前逻辑组拆分总额 × 占比 ÷ 数量。
- 拆分“金额”：拆分单价 × 数量；“摊后金额”与拆分金额逐行一致。
- “单价2”：原金额 ÷ 数量；“手续费1%”：`ROUND(原金额 × 1%, 2)`；“最终金额”：应收合计 - 手续费。
- A 列“标记”包含“拆分”时，同一网店订单号跨物流单合并拆分，应收只计一次；包含“合并”时，同一物流单内不同网店订单的应收分别计入后合并拆分。
- 自动生成“透视表”核对页。有手续费模式核对最终金额与摊后金额；无手续费模式按标记后的逻辑组核对应收与摊后金额。差异直接写入数值，非零差异会醒目标红。
- 自动生成“汇总”页。有手续费模式按“原金额－手续费－摊后金额”核对；无手续费模式按“应收合计－摊后金额”核对。
- 所有新增计算列均使用标准四舍五入并保留两位小数；每个订单最后一个有效行吸收分币尾差，保证拆分金额和摊后金额合计严格等于两位小数的订单目标金额。
- “单价2”、手续费和最终金额保留可核对的工作表公式，其中手续费使用 `ROUND(...,2)`；透视表金额与差异也统一按两位小数核对。
- “订单金额”和“应收合计”的外部公式会使用源文件中的已计算结果固化为数值，避免保存后显示为空；没有缓存值时会提示先用 Excel/WPS 打开并保存源文件。

## 运行源码

```powershell
python splitter_worker.py --fee-mode fee 占比表.xlsx 销售单.xlsx 输出.xlsx
python splitter_worker.py --fee-mode no-fee 占比表.xlsx 销售单.xlsx 输出.xlsx
```

省略 `--fee-mode` 时保持兼容，默认按有手续费模式运行。

## 测试与打包

```powershell
.\build.ps1
```

打包完成后，程序位于 `outputs\组合装单价拆分工具.exe`，可直接复制到其他 Windows 电脑运行。

如需指定打包使用的 Python，可先设置 `BUNDLE_SPLITTER_PYTHON` 环境变量。真实样例回归测试可通过 `BUNDLE_SPLITTER_RATIO_SAMPLE` 和 `BUNDLE_SPLITTER_SALES_SAMPLE` 指定本机文件，不会把业务表上传到仓库。
